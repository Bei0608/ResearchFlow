# ResearchFlow V1.1 项目证据与简历素材

> 本文是可复用项目证据，不是针对具体JD定制后的最终简历。未提供目标JD前，不把
> 技术关键词或推断写成经历事实。

## 项目背景与目标

ResearchFlow最初是面向RT-1、RT-2、PaLM-E等具身智能论文的多用户RAG/Agent研究
助手。V1.1在原有Agent上增加评测中台：管理不可变Agent/数据集/量表版本，持久化
程序运行，完成人工评审、统计、报告、Baseline对比和CI质量门禁闭环。

## 实际完成的工作

- 建立PDF清洗、重叠分块、SHA-256稳定ID及Milvus幂等增量索引，避免重复Embedding；
- 以LangChain Agent支持开放工具决策，以LangGraph固定严格问答、拒答和异常降级；
- 使用PostgresSaver、PostgresStore和thread所有权分别处理会话状态、长期偏好和隔离；
- 建立Workspace作用域、不可变Agent/评测集/量表版本及逐案例Evaluation Runner；
- 将程序指标与人工评分分表，人工草稿、提交和纠错均以不可变Revision留存，使用
  乐观锁与幂等键处理并发和重复保存；
- 聚合最新有效提交，输出样本/缺失/完成率及可追溯JSON/HTML报告；
- 建立每应用活动Baseline和版本化Gate Policy，支持绝对下限、最大回退以及
  `PASSED/FAILED/INCOMPLETE`三态结论；
- 提供无模型、无私有PDF的原创demo与幂等bootstrap，并在CI从空PostgreSQL迁移后
  连续初始化两次；
- 使用Argon2、JWT轮换撤销、资源绑定MCP Token、Redis共享限流和审计保护多用户API。

## 已验证结果（截至2026-11-06）

- 132项pytest通过，包含单元和真实PDF集成测试；
- 隔离空PostgreSQL由零迁移到`0007_v11 (head)`，连续bootstrap两次复用相同业务ID；
- API端到端完成4案例草稿保存、幂等重试、纠错、4/4提交、统计、双格式报告和Gate；
- 跨用户读取评审资源返回404；窄屏评审页无全局横向溢出，控制台无错误；
- 18条可回答检索题：Hit@5=1.000、Mean Recall@5=1.000、MRR=0.972；
- 10条答案评测：综合分0.988、路由准确率1.000、关键词召回0.967；
- MCP真实检索、长期记忆写读删、Refresh轮换/撤销均在现有容器环境复测通过。

上述检索/答案指标仅代表仓库内论文集；demo程序指标用于流程验收，不代表新一轮
模型推理；项目没有预填或虚构人工评分，也没有生产用户、成本或收入数据。

## 可用于简历的基础要点

- 将论文RAG Agent扩展为版本化评测中台，统一管理Agent、数据集、量表、运行、人工
  修订、聚合报告与发布门禁，形成从实验事实到发布结论的可审计链路。
- 设计程序指标/人工评分分离模型，以不可变Revision、乐观锁和幂等键实现草稿恢复、
  完整提交及提交后纠错，确保统计只读取最新有效提交且保留历史。
- 实现Baseline质量门禁，按指标来源/评估器版本精确匹配绝对阈值与最大回退规则，
  对缺失数据返回INCOMPLETE，并以明确退出码接入GitHub Actions。
- 构建可复现交付链路：Alembic七阶段迁移、Docker Compose、原创无模型demo、空库
  幂等初始化和132项测试；真实论文集检索Hit@5/Recall@5达到1.000、MRR 0.972。
- 同时实现开放式LangChain Agent与确定性LangGraph Workflow，并通过带页码证据、
  阈值拒答、Redis版本化缓存及MCP受保护工具服务提升可追溯性和工程可靠性。

## 关键取舍与面试证据

- 采用模块化单体而非微服务：当前规模优先事务一致性和低部署成本；
- 采用Jinja2+原生JavaScript而非React：以最小方案完成真实评审操作验收；
- 同步Runner逐案例落库：单案例失败仍保留已完成事实；长任务异步化留作增强；
- 缺失评分记为INCOMPLETE而非0分：区分“没有事实”和“质量失败”；
- 固定demo与真实在线评测分开：前者保证CI可重复，后者证明当前模型/语料质量；
- 环境变量优先于`.env`：隔离验收曾发现覆盖导致误连主库，修复后加入回归测试和CI。
