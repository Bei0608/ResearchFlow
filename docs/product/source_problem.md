# 原题与需求来源

## 当前状态

截至 2026-11-05，项目目录和对话中没有一份独立、逐字完整的比赛题目、课程作业
题目或企业需求原文。因此当前不能把任何推断描述为“原题明确要求”。

## 已收到的直接要求

用户明确给出的开发原则如下，保持原意记录：

1. 以原题为验收依据，区分必做功能、可选增强和范围外内容；
2. 优先保证评审、保存、修改、统计、报告的完整业务流程；
3. 采用满足要求的最小技术方案，并说明关键选择以及代价；
4. 所有运行数据随项目提供，人工评分与程序测试数据需要明确区分；
5. 实现过程中持续维护需求清单、决策记录、项目状态和真实对话记录；
6. 每个阶段说明完成内容、实际验证结果、遗留问题和下一步；
7. 影响业务规则或项目范围的决定先给出选项和建议，常规实现细节自主处理。

此前已确认的产品方向是：将 ResearchFlow 从单一论文 RAG 助手逐步建设为面向
RAG/Agent 应用的数据与自动化评测平台，优先建设评测实验中心。

## 后续补充规则

冲突项进入 `ambiguities.md`，在确认前暂停受影响实现。
