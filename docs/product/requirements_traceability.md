# 需求与验收方式对应表

## 使用说明

- `MUST`：本阶段交付不可缺少；
- `SHOULD`：可增强专业度，但不得阻塞必做闭环；
- `OUT`：当前范围外，不应暗示已经支持；
- 状态中的 `PARTIAL` 表示本阶段基础已验证，但完整业务验收依赖后续阶段；
- 验收证据分为自动化测试、人工操作记录、数据库/报告产物三类；
- 原题全文尚未提供，表中来源为用户直接要求或已确认项目方向。

## V1.1 总体验收场景

评审人使用项目自带演示数据登录，选择一个已完成的 Agent 运行，打开案例，查看
程序指标与证据；填写量表并保存草稿；退出后重新进入并修改；提交评审；管理员
查看完成率和分数统计，生成 HTML/JSON 报告；报告分别显示程序评分和人工评分，
并把 Candidate 与 Baseline 的门禁结果写清楚。全过程不得依赖未随项目提供的私有
数据，且另一个用户不能访问这些资源。
